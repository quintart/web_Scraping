# Web Crawling — 2-Hour Hands-On Course

**Format:** Project-based. You'll write and run code in every module.
**Prerequisite:** Comfortable with Python basics (loops, functions, dicts).
**Setup:** `pip install requests beautifulsoup4 scrapy selenium lxml`

---

## Module 1 (0:00–0:20) — Foundations & Your First Scraper

**Concepts (5 min)**
- Crawling vs. scraping: traversal vs. extraction
- How a page becomes HTML you can parse: request → response → DOM tree
- The anatomy of an HTTP request: method, headers, status codes (200, 403, 404, 429)

**Build (15 min)**
Write a script that fetches `http://books.toscrape.com` and extracts all book titles + prices using `requests` + `BeautifulSoup`.

**Checkpoint:** You should have a working script that prints 20 book titles and prices to the console.

---

## Module 2 (0:20–0:40) — Parsing Deep Dive: CSS Selectors & Navigating the DOM

**Concepts (10 min)**
- `find()` vs `find_all()` vs `select()` (CSS selector syntax)
- Navigating parent/sibling/child relationships in the DOM tree
- Using browser DevTools (Inspect Element) to find the right selectors — this is the #1 real-world skill

**Build (10 min)**
Using DevTools, identify selectors for a real (scraping-friendly) site of your choice — e.g., Wikipedia's "Special:Random" or Hacker News (`news.ycombinator.com`). Extract titles + links for the top 10 items.

**Checkpoint:** A script that scrapes a site *you chose*, not one from a tutorial — proves you can read DevTools and generalize.

---

## Module 3 (0:40–1:00) — Crawling: Following Links & Pagination

**Concepts (5 min)**
- URL frontiers and queues (the core data structure of any crawler)
- Avoiding infinite loops: tracking visited URLs
- Politeness: `time.sleep()`, rate limiting, why it matters (server load + IP bans)

**Build (15 min)**
Extend Module 1's script to crawl 5 pages of `books.toscrape.com` by following the "next page" link programmatically (not hardcoding page numbers), storing all results in a single CSV.

**Checkpoint:** CSV with 100 books, generated by *following links*, not guessing URL patterns.

## Module 5 (1:10–1:35) — Handling Real-World Obstacles

**Concepts (10 min)**
- `robots.txt`: what it is, how to check it, how to respect it programmatically
- Common anti-bot defenses: User-Agent checks, rate limiting, CAPTCHAs, JS-rendered content
- Error handling: retries, timeouts, status code checks
- Legal/ethical boundaries: ToS, GDPR/personal data, "public" ≠ "permitted to scrape at scale"

**Build (15 min)**
Harden your Module 3 crawler:
- Check `robots.txt` before crawling (use Python's `urllib.robotparser`)
- Add a proper `User-Agent` header
- Wrap requests in try/except with retry logic (max 3 attempts, exponential backoff)

**Checkpoint:** A crawler that fails gracefully instead of crashing on a bad response.

---

## Module 6 (1:35–1:55) — JavaScript-Rendered Sites with Selenium

**Concepts (5 min)**
- Why `requests` can't see JS-rendered content (it doesn't execute JS)
- Headless browsers as the workaround
- When to reach for Selenium/Playwright vs. when `requests` is enough (check page source first!)

**Build (15 min)**
Use Selenium to scrape a JS-rendered element (e.g., a site that loads content via infinite scroll or an AJAX call). Extract data that wouldn't appear in a plain `requests.get()`.

**Checkpoint:** Side-by-side comparison — show that `requests` misses the data, Selenium catches it.

---

## Module 7 (1:55–2:00) — Wrap-Up & Where to Go Next

- **Scrapy**: when your crawler needs to scale beyond a single script (built-in concurrency, pipelines, middleware) — worth learning once you outgrow `requests`+`BeautifulSoup`
- **APIs first**: always check if the target site has an official API before scraping
- **Storage**: moving from CSV to SQLite/Postgres once data volume grows
- **Next project ideas** (OSINT-flavored, since that's your direction):
  - Build a crawler that monitors a public forum/subreddit for keyword mentions
  - Build a tool that maps a company's public web presence (subdomains, linked pages)
  - Build a change-detection crawler (alerts when a page's content changes)
